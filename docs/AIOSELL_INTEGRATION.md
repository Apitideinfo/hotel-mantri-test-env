# Hotel Mantri PMS × Aiosell Integration

This document outlines the architecture and endpoints of the Hotel Mantri inbound Aiosell Channel Manager integration.

## Environment: Sandbox / Test

**Public Reservation Endpoint:**
`https://YOUR-DOMAIN.com/api/integrations/aiosell/reservations`
*(Replace YOUR-DOMAIN.com with the actual deployed domain configured in `APP_BASE_URL`)*

**Supported Operations:**
- `book`
- `modify`
- `cancel`

## Authentication

The webhook endpoint requires **HTTP Basic Authentication**.

- **Header Format:** `Authorization: Basic <base64(username:password)>`
- **Credentials:** Aiosell must be provided with the custom webhook credentials configured securely on the Hotel Mantri server (`AIOSELL_WEBHOOK_USERNAME` / `AIOSELL_WEBHOOK_PASSWORD`).

> [!WARNING] 
> Do not use your Aiosell Partner API credentials as the webhook authentication. The webhook credentials are generated by the PMS to authenticate incoming traffic from Aiosell.

## Integration Endpoints

### 1. Inbound Reservation Webhook

- **Endpoint:** `POST /api/integrations/aiosell/reservations`
- **Content-Type:** `application/json`

**Expected Payload:**
```json
{
  "action": "book",
  "hotelCode": "sandbox-pms",
  "bookingId": "AIOSELL-RES-12345",
  "roomCode": "STD",
  "rateplanCode": "EP",
  "guestName": "John Doe",
  "guestPhone": "+1234567890",
  "checkIn": "2026-09-01",
  "checkOut": "2026-09-03",
  "roomsCount": 1,
  "amount": 5000,
  "paymentStatus": "paid"
}
```

**Responses:**
- `200 OK`: `{"success": true, "message": "Reservation created"}`
- `401 Unauthorized`: Missing or invalid Basic Auth header.
- `400 Bad Request`: Invalid payload structure.
- `404 Not Found`: Hotel Code or Room Code mapping could not be found.
- `500 Internal Server Error`: An unexpected error occurred.

### 2. Health Check

- **Endpoint:** `GET /api/integrations/aiosell/health`
- **Purpose:** Verifies that the PMS is online, the integration module is active, and webhook configurations are properly loaded.

### 3. Webhook Info

- **Endpoint:** `GET /api/integrations/aiosell/webhook-info`
- **Purpose:** Exposes the exact absolute URL Aiosell should configure on their end for the webhook.

## Processing Behavior

### Idempotency
- Incoming requests are identified by `bookingId` (the external Aiosell reservation ID).
- Duplicate `book` requests with the same `bookingId` will return an idempotent `200 OK` (Already imported) without creating duplicate reservations.
- Modification events strictly target the existing reservation via the `bookingId`.

### Property & Room Mapping
- **Hotel Mapping:** `hotelCode` is strictly mapped against internal Hotel Mantri properties. Unknown codes are rejected (`404`).
- **Room Mapping:** `roomCode` and `rateplanCode` are mapped via the Channel Manager mapping tables (`channel_rate_mappings`). The system dynamically translates external OTA codes into the actual PMS room category IDs and internal rate plan identifiers.

### Error Handling & Retry Behavior
- Aiosell should observe HTTP status codes.
- Responses in the `4xx` range (e.g. `400`, `401`, `404`) represent client/mapping errors and **should not be retried infinitely**.
- Responses in the `5xx` range indicate transient backend issues and may be retried using exponential backoff.
- The PMS itself observes the Aiosell API rate limit (40 req/min) for outbound updates and utilizes exponential backoff internally (2s, 5s, 10s) on `429` and `5xx` responses.
